# v0.2 — Configurable Actions

## Context

v0.1 ships exactly one action: **Open Terminal Here**. The `Action` protocol + `ActionRegistry` are in place but only one action exists, and nothing is user-configurable.

v0.2 extends the system so most of the high-value right-click features for a developer (open in any editor, run a terminal command, move to a folder, create a file from a template) can be added by dropping a JSON file into `~/Library/Application Support/TermHere/`, without recompiling.

This spec covers the architectural investment plus five concrete actions that exercise it.

## Goals

1. **Architectural seam for "configurable, list-style" actions.** Adding a new "Open With X" or "Run Y" should be one JSON file, no Swift.
2. **Five concrete actions live in v0.2**, organized as a nested submenu so future growth doesn't crowd the right-click menu.
3. **Zero-config out of the box.** Built-in presets ship with the app and self-install on first launch; users can edit, disable, or extend them.
4. **Backward compatible.** v0.1's `OpenTerminalAction` and the `Action` protocol stay; `MenuBuilder` extends to handle group actions.

Top-level entries are the two highest-frequency actions; everything else lives in typed submenus that scale.

## Architecture

### Protocols

```swift
// Existing — unchanged
protocol Action {
    var id: String { get }
    var title: String { get }
    var icon: NSImage? { get }
    func isAvailable(in context: SelectionContext) -> Bool
    func run(in context: SelectionContext)
}

// New — for "this Action expands into a submenu of sub-actions"
protocol GroupAction: Action {
    /// Submenu title shown under TermHere. Defaults to `title`.
    var submenuTitle: String { get }
    /// Called when the menu is being built; returns the live list of sub-actions.
    /// Implementations read JSON from disk here.
    func loadItems(in context: SelectionContext) -> [Action]
}
```

A `GroupAction`'s own `run(in:)` is never invoked — `MenuBuilder` recognizes it and builds a submenu from `loadItems` instead.

### Action types in v0.2

| Type | Conforms to | Source of items |
|---|---|---|
| `OpenTerminalAction` | `Action` | hardcoded (v0.1) |
| `CopyPathAction` | `Action` | hardcoded |
| `OpenWithAction` | `GroupAction` | `open-with/*.json` |
| `RunCommandAction` | `GroupAction` | `run/*.json` |
| `MoveToAction` | `GroupAction` | `move-to/*.json` |
| `NewFileAction` | `GroupAction` | `new-file/*.json` |

`ActionRegistry.actions` becomes the ordered list of all six. `MenuBuilder` is updated to:
- For `Action`: add one menu item under `TermHere`
- For `GroupAction`: add a submenu under `TermHere` whose items come from `loadItems`
- Insert a separator between top-level items and group submenus

### MenuBuilder pseudocode

```swift
for action in ActionRegistry.actions where action.isAvailable(in: ctx) {
    if let group = action as? GroupAction {
        let items = group.loadItems(in: ctx)
        guard !items.isEmpty else { continue }
        // submenu titled group.submenuTitle, containing one item per sub-action
    } else {
        // top-level menu item, tag-based dispatch as in v0.1
    }
}
```

Sub-action click dispatch reuses the existing `tag → ActionRegistry` mechanism by extending the controller to also track sub-actions for the current menu invocation.

## Config layout

```
~/Library/Application Support/TermHere/
├── open-with/
│   ├── vscode.json      ← preset, written on first launch
│   ├── cursor.json
│   └── iterm.json
├── run/
│   ├── claude.json
│   └── codex.json
├── move-to/             ← empty; user-only
└── new-file/
    ├── markdown.json
    └── python.json
```

`ConfigBootstrapper` (rename of `TemplatesFolderBootstrapper`) runs on host-app first launch and:
1. Creates the four subdirectories if missing.
2. For each preset, **writes the JSON only if a file with that name doesn't already exist** — never overwrites user edits.
3. Never deletes anything the user has put there.

Removing a preset = delete its JSON. Editing = edit the JSON.

The extension reads the JSON files **every time the menu is built**. This avoids stale state and is cheap (< 20 small files).

Within a subdir, items appear in the menu sorted by their `title` field (case-insensitive). Filenames are not user-facing; rename freely.

## JSON schemas

Schemas are intentionally narrow — anything beyond what's needed is YAGNI'd.

### `open-with/*.json`

```json
{
  "title": "Visual Studio Code",
  "bundleId": "com.microsoft.VSCode",
  "args": ["{path}"],
  "showOnlyIfInstalled": true
}
```

- `bundleId` is resolved via `NSWorkspace.urlForApplication(withBundleIdentifier:)`
- `args` is the argv passed to `NSWorkspace.openApplication(at:configuration:)` after template substitution
- If `showOnlyIfInstalled` is true and the bundle isn't installed → entry is silently skipped

### `run/*.json`

```json
{ "title": "Claude", "command": "claude" }
```

- Implemented by reusing the AppleScript path from `OpenTerminalAction`: `tell app Terminal to do script "cd {path} && command"`
- `command` runs literally; the user is responsible for it being on `$PATH`

### `move-to/*.json`

```json
{ "title": "Archive", "destination": "~/Documents/Archive" }
```

- `destination` supports `~` expansion
- Move uses `FileManager.moveItem(at:to:)` per selected URL; conflicts get `" 2"` / `" 3"` suffix
- No confirmation dialog; macOS undo (⌘Z in Finder) handles mistakes for the common case

### `new-file/*.json`

```json
{
  "title": "Markdown",
  "extension": "md",
  "filename": "Untitled",
  "content": "# {filename}\n\n"
}
```

- Creates `{filename}.{extension}` in the target directory
- If a file with that name exists, appends `" 2"` / `" 3"`
- `content` supports `{filename}` and `{name}` template variables

## Template variables (shared across all action types)

| Token | Replaced by |
|---|---|
| `{path}` | Absolute POSIX path of `SelectionContext.targetDirectory` |
| `{filename}` | Name of the new/selected file including extension |
| `{name}` | Same as `{filename}` but with extension stripped |

Substitution is plain string replacement (no shell escaping). Where shell escaping is needed (e.g., `RunCommandAction`'s AppleScript `do script`), the Swift code applies it after template substitution.

## Out of scope for v0.2

- **Permanent delete** — discussed in brainstorming; UX risk needs a separate design.
- **Folder real size** — needs async + notifications; deferred.
- **Per-action keyboard shortcuts** — Finder Sync extensions can't bind keys anyway.
- **GUI config editor** — JSON files are good enough for now.
- **Conflict UX for moves** — silent rename with suffix is the v0.2 behavior; a "replace? skip?" dialog can come later.

## Verification

1. Fresh install: launch host app → confirm 4 subdirs created in App Support with expected preset files.
2. Disable a preset: delete `open-with/vscode.json`, right-click → confirm VS Code entry gone.
3. Add a custom entry: drop `open-with/zed.json` with valid bundle id → re-right-click → Zed appears.
4. Uninstalled app: `open-with/cursor.json` exists but Cursor isn't installed → entry hidden.
5. Copy Path: right-click a file → click Copy Path → pasteboard contains the path; multi-select gives newline-joined paths.
6. Run claude: right-click a folder → Run in Terminal → Claude → Terminal opens at that folder and `claude` is executed.
7. Move To: configure `move-to/archive.json`, right-click a file → Move To → Archive → file moves; ⌘Z in Finder reverses it.
8. New File: right-click a folder → New File → Markdown → `Untitled.md` appears with content `# Untitled\n\n`. Repeat → `Untitled 2.md`.
9. Empty area: right-click empty space in a Finder window → confirm Move To submenu is absent (no selection to move), others present.
